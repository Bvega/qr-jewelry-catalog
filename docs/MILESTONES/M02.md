# 5. APPROVED NORMALIZED FIND MODEL

Each normalized Find must support these fields:

```text
publicId
legacyId
slug
title
collection
description
condition
availability
price.amount
price.currency
photos[]
primaryPhoto
altText
relatedFindIds[]
featured
createdAt
updatedAt
```

## 5.1 Required values for current records

For all five current records:

- `publicId`: required permanent string
- `legacyId`: required existing numeric ID
- `slug`: required stable lowercase kebab-case string
- `title`: exact current title
- `collection`: `jewelry`
- `description`: exact current description
- `condition`: `null` unless the existing record explicitly provides a condition
- `availability`: exact current value
- `price.amount`: exact current numeric price
- `price.currency`: `USD`
- `photos`: array containing the current image path when one is present
- `primaryPhoto`: current image path when one is present, otherwise `null`
- `altText`: descriptive string based on the current item title
- `relatedFindIds`: public IDs corresponding exactly to current `relatedIds`
- `featured`: `false` unless the existing data already defines an equivalent state
- `createdAt`: `null`
- `updatedAt`: `null`

Do not invent dates, conditions, product history, or descriptive claims.

## 5.2 Permanent public IDs

Assign exactly:

```text
legacyId 1 → BU-0001
legacyId 2 → BU-0002
legacyId 3 → BU-0003
legacyId 4 → BU-0004
legacyId 5 → BU-0005
```

Rules:

- Public IDs are immutable.
- Public IDs are unique.
- Public IDs are never recycled.
- Future records continue the sequence.
- Public IDs must not depend on the item title or availability.

## 5.3 Slugs

Create one stable slug per current title.

Rules:

- lowercase;
- ASCII;
- kebab-case;
- unique;
- no price, availability, or mutable wording;
- documented in the identifier registry;
- changing a title later must not automatically change an established slug.

If a title does not produce a unique slug, append the permanent public ID suffix.

# 6. COMPATIBILITY CONTRACT

The current application must continue to receive:

```text
window.JEWELRY_ITEMS
```

with the exact field structure and values expected by `app.js` and `item.js`.

The normalized source must also be available as:

```text
window.BETWEEN_US_FINDS
```

## 6.1 Adapter requirements

The legacy adapter must expose, for each record:

```text
id
name
price
description
image
category
availability
relatedIds
```

Requirements:

- `id` comes from `legacyId`;
- `name` comes from `title`;
- `price` comes from `price.amount`;
- `description` is unchanged;
- `image` comes from `primaryPhoto`;
- `category` remains compatible with current rendering;
- `availability` is unchanged;
- `relatedIds` are translated from `relatedFindIds` back to numeric legacy IDs.

No current renderer may require modification solely because of the normalized model.

## 6.2 Source-of-truth rule

There must be one authoritative set of current item values.

Do not maintain two manually duplicated catalog datasets.

The legacy array must be derived from the normalized Finds.

## 6.3 Global exposure

Use browser globals compatible with the existing static architecture.

Do not introduce ES module loading, a bundler, a framework, or asynchronous data loading during M02.
