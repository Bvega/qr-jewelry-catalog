# 5. IN SCOPE

## 5.1 Automated baseline validation

Create a dependency-free validation system using only capabilities already available in the repository environment, preferably Node.js built-in modules and the Node test runner.

The validation must cover:

### JavaScript syntax

Validate syntax for:

- `app.js`
- `item.js`
- `data/items.js`

### Static page contracts

Verify that:

- `index.html` exists;
- `item.html` exists;
- required application scripts are referenced;
- the shared stylesheet is referenced;
- the item detail page loads the QR library before `item.js`;
- required catalog and item-detail DOM anchors still exist.

### Data contracts

Load and validate the existing records from `data/items.js`.

At minimum, validate:

- the catalog array exists;
- all current item IDs are present;
- IDs are unique;
- required fields exist;
- prices are valid numbers;
- availability values belong to the existing allowed set;
- related IDs reference existing records;
- image paths are strings when provided;
- records remain compatible with the current catalog and detail renderers.

The existing missing-photo behavior may be recorded as a known baseline condition. Do not alter product records merely to make a test pass.

### Legacy URL compatibility

Create automated contract checks proving that every current numeric item ID remains addressable through:

```text
item.html?id=N
```

The checks must cover all current records.

A browser automation dependency is not approved. Use a dependency-free method appropriate to the current static architecture.

### Static serving smoke validation

Create a dependency-free smoke check that serves or reads the static site and verifies that essential public resources can be reached successfully.

At minimum, verify:

- `/`
- `/index.html`
- `/item.html?id=<existing-id>`
- `/styles.css`
- `/app.js`
- `/item.js`
- `/data/items.js`
- each existing real image asset

Do not require unavailable image files to pass as though they exist. Record known missing assets as warnings.

### QR compatibility contract

Verify that:

- `item.html` still references the approved QR library;
- `item.js` still contains the existing QR generation path;
- the application retains a graceful fallback when the QR library is unavailable;
- no existing QR or share URL behavior is removed.

## 5.2 Repeatable validation command

Provide one primary command that runs the complete M01 validation suite.

The command must:
