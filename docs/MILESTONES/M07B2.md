
- description: required, trimmed, 1–5000 characters;

# 14. SAVE BEHAVIOR

Creating a Find:

1. validate locally;
2. insert as draft unless publish is explicit;
3. receive generated UUID and public ID;
4. upload optional primary image;
5. create primary photo metadata;
6. report success only after completed operations;
7. provide honest partial-failure recovery.

Editing must update only approved fields, preserve database-controlled values, refresh the list after success, and prevent duplicate submit.

Archiving must set `archived_at`, set `is_published` false, preserve the record/image, and allow restore. Restoring clears `archived_at` and remains hidden until explicitly published.

# 15. PRIMARY IMAGE WORKFLOW

Support one primary image per Find in M07B-2.

Accepted MIME types:

```text
image/jpeg
image/png
image/webp
```

Maximum size: `10 MiB`.

Before upload:

- validate MIME and size;
- obtain width and height;
- show local preview;
- require alt text.

Storage path:

```text
finds/{find-uuid}/{unique-filename}
```

For new images, upload first and then insert metadata. If metadata insertion fails, remove the new object as best-effort cleanup.

For replacement, upload the new object, update the existing primary metadata row, then remove the old object only after database success. On database failure, remove the newly uploaded object and preserve the old valid image.

Use the public Storage object URL for display. Do not anonymously enumerate the bucket.
