# 13. IDEMPOTENCY AND PARTIAL FAILURE

Per public ID:

- absent: create;
- fully exact: mark complete and skip;
- exact Find with incomplete primary-photo step: allow verified resume;
- any field, slug, Collection, visibility, photo metadata, or Storage mismatch: stop;
- never overwrite a mismatch.

New-record order:

1. revalidate dry-run;
2. ensure Collections exact;
3. insert explicit public ID and slug as hidden draft;
4. receive generated UUID;
5. upload verified image to `finds/{find-uuid}/{approved-filename}`;
6. insert primary photo metadata;
7. verify;
8. continue.

If upload or metadata fails for a newly inserted Find:

- remove only the new object if created;
- remove only the newly inserted incomplete Find;
- report rollback result;
- never delete pre-existing data.

If rollback fails, stop remaining records and report recovery state without credentials or UUIDs.
