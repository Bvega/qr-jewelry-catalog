# 3. APPROVED SECURITY MODEL

```text
anon:
- read published, non-archived Finds;
- read Collection metadata;
- retrieve public product images;
- no write access.

authenticated non-admin:
- no catalog-management access.

catalog admin:
- create and update Finds;
- publish or hide Finds;
- change availability;
- manage relations and images.

browser:
- project URL and publishable key only;
- never a secret/service-role key.
```

Authentication alone must not grant administration. Use an explicit admin allowlist plus RLS.

# 9. FINDS

Create `public.finds` with at least:

```text
id uuid primary key default gen_random_uuid()
public_id text not null unique
slug text unique
legacy_id integer unique
title text not null
collection_id text not null references public.collections(id)
price_amount numeric(10,2) not null
price_currency text not null default 'USD'
availability text not null
description text not null
condition text
is_published boolean not null default false
is_featured boolean not null default false
sort_order integer not null default 0
published_at timestamptz
archived_at timestamptz
created_by uuid references auth.users(id)
updated_by uuid references auth.users(id)
created_at timestamptz not null default now()
updated_at timestamptz not null default now()
```

Constraints:

- `public_id` matches `BU-` plus at least four digits;
- title and description are nonblank and length-bounded;
- price is greater than zero;
- currency is `USD`;
- availability is `available`, `reserved`, or `sold`;
- `legacy_id`, when present, is positive;
- archive state is separate from availability.

Create a trigger that maintains audit fields and first publication timestamp without trusting client-supplied audit values.

Public RLS:

```text
anon/authenticated can select only:
is_published = true AND archived_at IS NULL
```

Admin RLS:

- admins can select all and manage records;
- authenticated non-admin users cannot manage records;
- drafts must never be public.


- at most one primary photo per Find;
- optional dimensions are positive.

Public may read photo rows only when the parent Find is published and not archived. Only admins may manage photo metadata.


Requirements:

- public retrieval;
- write operations controlled by RLS;

- HEIC is not a final public format;
- path convention: `finds/{find-uuid}/{unique-filename}`;
- owner filenames are never trusted as unique storage keys.

Define the bucket in `supabase/config.toml` when supported and reconcile hosted metadata safely in the migration.

Create `storage.objects` policies:

- admin-only insert;
- admin-only update;
- admin-only delete;
- admin listing as required;
- authenticated non-admin writes denied;
- no browser secret/service-role key.

Do not add real images beneath `supabase/`.
