# 6. OWNER INVENTORY TEMPLATE

Create:

```text
content-intake/finds-template.csv
```

Use UTF-8 CSV with this exact header order:

```text
intake_key,title,collection,price_amount,price_currency,availability,description,condition,primary_photo_filename,additional_photo_filenames,alt_text,related_public_ids,featured,owner_notes
```

Required fields:

```text
intake_key
title
collection
price_amount
price_currency
availability
description
primary_photo_filename
alt_text
```

Optional fields:

```text
condition
additional_photo_filenames
related_public_ids
featured
owner_notes
```

Rules:

- `intake_key`: unique lowercase ASCII kebab-case temporary ID;
- `collection`: one of `jewelry`, `vintage`, `home-decor`, `kitchen`, `collectibles`, `new-items`;
- `price_amount`: positive number, max two decimals, no currency symbol;
- `price_currency`: `USD`;
- `availability`: `available`, `reserved`, or `sold`;
- `description`: factual public copy, no unsupported claims;
- `condition`: optional and factual;
- `primary_photo_filename`: exact file name with extension;
- `additional_photo_filenames`: optional pipe-separated filenames;
- `alt_text`: concise visual description;
- `related_public_ids`: optional pipe-separated IDs;
- `featured`: `true`, `false`, or blank;
- `owner_notes`: internal only and never public automatically.

Create one clearly labeled non-production example row using:

```text
sample-find-do-not-publish
```

Do not use a real product title, real price, real ID, or existing image filename.

# 8. PHOTO FILE-NAMING STANDARD

Create:

```text
docs/CONTENT_PHOTO_NAMING.md
```

Approved pattern:

```text
{intake-key}-{sequence}.{extension}
```

Examples:

```text
blue-stone-bracelet-01.jpg
blue-stone-bracelet-02.jpg
vintage-serving-tray-01.webp
```

Allowed final public extensions:

```text
.jpg
.jpeg
.png
.webp
```

Rules:

- lowercase;
- ASCII letters, numbers, and hyphens only;
- no spaces or parentheses;
- unique filenames;
- two-digit sequence;
- primary photo uses `01`;
- preserve original high-resolution source elsewhere;
- HEIC is not accepted as final public format;
- document that HEIC requires later conversion to JPG or WebP;
- do not perform bulk conversion in M07A.

# 10. VALIDATOR

Create:

```text
scripts/validate-content-intake.mjs
```

Dependency-free and read-only.

Default behavior:

- validate `content-intake/finds.csv` if present;
- validate `content-intake/photo-manifest.csv` if present;
- if neither exists, validate tracked examples and report that owner intake is not yet present;
- never modify files;
- never create public IDs;
- never move photos;
- never modify live catalog files;
- exit nonzero on errors;
- exit zero when templates/examples are valid and no owner file exists.

Support:

```bash
node scripts/validate-content-intake.mjs --finds path/to/finds.csv --photos path/to/photo-manifest.csv
```

Minimum checks:

- required headers;
- duplicate headers;
- missing required values;
- duplicate `intake_key`;
- intake-key format;
- allowed Collection;
- positive price with max two decimals;
- currency `USD`;
- allowed availability;
- allowed boolean values;
- allowed photo extension;
- filename format;
- duplicate photo filenames;
- manifest intake key resolves;
- exactly one primary photo per Find when manifest exists;
- primary filename matches the Find row;
- positive integer sequence;
- owner-approved value valid;
- alt text present;
- unresolved relationships reported;
- owner notes never treated as public fields.

Warnings, not errors:

- condition blank;
- additional photos absent;
- owner approval false;
- referenced raw photo not present;
- Coming Soon Collection;
- unresolved proposed relationship clearly pending.

Output:

```text
Content intake validation: PASS
```

or:

```text
Content intake validation: FAIL
```

with concise errors and warnings.
